# crap4dart checking + CRAP badge

After ANY code change in this repository (`lib/`, `packages/*/lib/`, `test/`,
`tool/`), run crap4dart and refresh the CRAP badge. Never finish a coding
task without it.

## Prerequisites

```bash
dart pub global activate crap4dart   # idempotent; puts crap4dart on PATH
export PATH="$PATH:$HOME/.pub-cache/bin"  # needed when pub global bin is not on PATH
```

## Mandatory workflow after code changes

Run from the repository root:

1. Analyze CRAP and regenerate the badge in one step:

   ```bash
   crap4dart analyze --badge badges/crap.svg
   ```

   `analyze` always runs `flutter test --coverage` first (fresh coverage on
   every run — do not bother running the suite separately), prints the
   per-method CRAP report, then writes the badge.

   - Exit 0 — CRAP gate passed (default threshold 8.0). Continue.
   - Exit 2 — threshold exceeded. Fix the flagged methods (extract logic,
     add tests raising coverage) and re-run. Do NOT paper over it by
     raising `--threshold`; the badge must never be refreshed from a
     red run and left red.

   The badge is written on every run — green (max CRAP ≤ threshold),
   yellow (≤ 2× threshold), red (beyond), grey `N/A` (no coverage data).

2. Keep the README embed. `README.md` must contain, right under the
   project title:

   ```md
   ![CRAP](badges/crap.svg)
   ```

   If missing, add it. (`analyze --badge` prints this exact snippet at the
   end of every run.)

3. Commit the refreshed `badges/crap.svg` together with the code change.
   A stale badge (code changed, badge did not) is a failed task.

## Quality gates (ratchet mode)

`crap4dart check` runs the full gate suite (loc, test_coverage, complexity,
golden, hardcoded_strings, accessibility, public_docs, ...). The current
template codebase does not pass every gate, so do NOT block on a full
`check` — use diff mode, which fails only on violations on lines you
actually changed:

```bash
crap4dart check --diff-base main
```

- Exit 0 — your changed lines introduce no new gate violations. Done.
- Exit 2 — fix the reported violations on your changed lines and re-run.
- Pre-existing violations on untouched lines belong to full mode only —
  leave them alone.

## Rules

- Exit codes: 0 ok · 1 usage/config error · 2 threshold exceeded or gate
  failed. Treat 2 as a failed task until fixed.
- Never hand-edit `badges/crap.svg` — it is generated by `--badge`.
- Full runs take minutes (the test suite runs inside `analyze`) — start
  them as a background job and keep working while they finish.
